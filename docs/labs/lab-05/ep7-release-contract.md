# EP7 implementation interface and test plan

12 November 2026, B / Datakung, Issue22. Implementation candidate for A review before any main release/cloud execution. The identity/scoped permissions/main/deploy.yml/demo interface was accepted in PR34 and actual EP6 evidence in PR38; this document does not claim prior approval of the new code.

Follow guide7.1-7.7 and the starter deploy.yml/release.sh. Keep the existing CI workflow and both protected branches. Combine accepted EP6 documentation with the first EP7 main release rather than creating an extra documentation-only release. Issue21 remains open until that reviewed release/tree acceptance. A reviews B's staging PR, then the separate staging-to-main release. Do not bypass either gate.

- First release A: main push -> reusable CI -> build runtime/tools locally -> WIF -> push both full-SHA tags -> resolve both digests -> preflight existing service/job -> awaited migration -> new revision without traffic -> verify its digest/Ready -> route100% to that exact revision -> public DB-backed health/UI smoke -> source/digests/job/revision/URL summary.
- Build before authentication to avoid consuming the short GitHub OIDC lifetime during Docker compilation. Use a masked short-lived impersonated access token for subsequent gcloud calls; no service-account key or stored deploy password. No new IAM role is needed.
- The public entry point remains `bash deploy/release.sh`; a Python standard-library helper handles JSON/argument lists and validation. The helper rejects non-main events, dirty/stale source, mismatched source tags, invalid settings and non-ancestor rollback tags before any cloud call. No bootstrap/API/IAM/SQL/secret-creation command is allowed.
- Preserve existing APP_ORIGIN, runtime/migration identities, Cloud SQL/secret bindings and service settings. Read the existing APP_ORIGIN for smoke; do not substitute a different Cloud Run URL. Runtime and tools image paths stay separate. Normal release updates the migration job command to `npm run db:migrate` so bootstrap seed is not replayed. Secret references remain on their existing accounts and are never read as payloads by the deployer.
- Rollback: workflow_dispatch on main with an existing full accepted-ancestor SHA; reuse runtime digest, skip CI/build/tools/job/migration/seed, verify/route the selected revision and smoke. Database/schema is not rolled back; use compatible images/additive migrations. No automatic rollback after a service/traffic/smoke failure.
- Revision suffix includes target SHA/run ID/attempt; reruns create an identifiable revision. Migration failure prevents any service update. Verify the created immutable revision before traffic, then verify traffic/config before exporting success values.
- Guide7.3 optional login smoke is deliberately skipped: reuse StudyTrack's existing public DB-backed `/api/health` and built UI checks; authenticated domain acceptance remains a separately recorded human check.
- Guide7.7 visible-change release B is a later reviewed change. Coordinate EP8 baseline after A but before B so the same accepted release proves repeatability and persistence; no artificial extra EP8 code release is required.

Offline tests cover successful ordering/two images/origin/export, normal/rollback boundaries, invalid inputs/ref/source, stale/dirty checkout, non-ancestor rollback, image/config drift, migration/update/revision/traffic failures and no success export after failures. They run with a fake command runner; no GCP, credential, real DB or Docker daemon is used. Existing bootstrap/smoke tests stay in CI. CI must also build both actual Docker targets. Live auth/deploy/visible change/persistence are NOT RUN until the reviewed main workflow executes.

Primary mechanics: [auth](https://github.com/google-github-actions/auth), [gcloud access-token environment](https://docs.cloud.google.com/sdk/docs/authenticate#use_the_gcloud_cli_with_an_access_token), [job update](https://docs.cloud.google.com/sdk/gcloud/reference/run/jobs/update), [waited execution](https://docs.cloud.google.com/sdk/gcloud/reference/run/jobs/execute), [service update](https://docs.cloud.google.com/sdk/gcloud/reference/run/services/update), [traffic](https://docs.cloud.google.com/sdk/gcloud/reference/run/services/update-traffic).
