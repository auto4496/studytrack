## Accepted contract and implemented behavior

B explicitly approved the [pre-code contract](../sprints/sprint-2/f05-lifecycle.md) in [PR32](https://github.com/auto4496/studytrack/pull/32) at `4ba7c768bf0d6e245387d9ebaa499fbbcd0ac933`. Implementation starts from accepted staging `001bdb0` (contracts PR32/33 merged). This candidate implements the accepted future-start409 rule, tomorrow-only pending target, inclusive retry-safe stop, frozen archived target display, shared-manager metadata and one-way deactivation without altering snapshots.

Participant APIs: PATCH `/api/goals/:goalId/target` and POST `/api/goals/:goalId/stop`; manager APIs: PATCH `/api/templates/:templateId` and POST `/api/templates/:templateId/deactivate`. Goal reads/mutations add pendingTarget. Existing entry/progress reads retain their date-effective denominators. Lifecycle writers use owner-scoped goal or shared-catalog template FOR UPDATE locks compatible with the existing F03/F04 FOR SHARE paths. No schema, migration, package/lock, auth or deploy workflow change is required.

The goal UI shows current/pending targets, confirms stopping and keeps eligible historical entries usable; the list filters ACTIVE/ARCHIVED. Manager cards edit metadata and confirm deactivation. Uncertain writes re-read the authoritative record before manual retry, block unsafe replay if the read fails, and clear private views on revoked sessions. Goal mutations invalidate/remount the activity component so old progress responses cannot overwrite refreshed data.
